# 对话记账游客三轮体验

## 行为与接口

游客直接访问 `/ledger/chat`。`GET /api/ledger/chat/session` 首次创建独立游客，返回 `isGuest`、`remaining`（3 至 0）、`limit`（3）、`identityKey` 和 `adoptedGuestKey`。`GET /api/ledger/chat/history` 返回该身份的消息、草稿及游客状态。已有统一登录优先验证，失效或账号服务故障不能降级创建游客。

文字和图片沿用原对话流程。成功完成的模型回复扣一次，失败释放既有会话租约；第三次回复完整可见，第四次发送要求登录。与原接口一致，业务错误使用 HTTP 200 的 `{code:403,message:...}`；身份及来源过滤错误使用 HTTP 401/403。同一成功 `requestId` 的重复请求返回已保存结果，不再扣次，即使额度已为零或模型暂不可用。

游客允许读取自己的对话、上传图片和编辑临时草稿。正式确认入账和账本等功能继续要求登录。每个功能的游客额度独立。

## 持久化与接续

Flyway `V10__ledger_guest.sql` 新增游客会话表。随机不透明 Cookie `dg_guest_ledger` 为 HttpOnly、Secure、SameSite=Lax、Path=/，180 天有效；数据库只保存令牌摘要。每个游客有独立用户、分类和聊天数据。额度保存在数据库，刷新或重启不重置。创建游客受可信 Origin 与现有 IP 限流约束，默认每小时 20 次。

额度和请求幂等受现有用户/会话锁及 90 秒可恢复租约保护，等待模型时不持有数据库事务。登录后在事务内迁移消息、草稿、草稿明细及附件归属，映射分类并处理请求编号冲突，保留账号原账本及当前草稿。已迁入的游客停用，旧游客凭证无法读取账号私有内容。

`adoptedGuestKey` 只在后端验证当前账号确实接收了所持游客 Cookie 时返回，用于浏览器未发送输入接续。客户端不能用本地存储自行决定数据归属。

## 验证

Java 21 下执行 `mvn package`：本次新生成的默认测试报告共 131 项通过，包含 13 项游客 HTTP 测试。旧目录中的 11 项集成测试报告不计入本次结果。本地未启动 Docker；依赖 MySQL 的集成验证使用上线前的私有数据库副本。

发布使用测试通过的 JAR，先备份生产数据库，在独立 MySQL 副本运行 Flyway，核对所有原业务表校验值，检查游客会话、空历史及跨站拒绝，再切换镜像。保留上一版镜像和启动描述以供回退。
